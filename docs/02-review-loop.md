# 02 · 审阅闭环

Space 的闭环是「用户提出修改 → Agent 提交具体建议 → 用户逐条决策 → 用户主动发送评论」。所有入口都遵循同一组约束：正文只通过用户接受的建议改变，评论只在用户显式发送时进入对话。

## 入口

- 左侧栏 **Space** 打开文档首页，浏览文档、待处理建议和评论。
- 对话输入框 **+** 中的 **Space 文档** 选择一个或多个文档加入当前对话，引用格式为 `space:<docId>`。
- 已发送的引用显示为文档卡片；点击卡片在右侧边栏打开对应审阅面板。
- Agent 通过 `space_document_read` 读取用户选中文档的最新正文、版本和待处理建议，通过 `space_suggest` 提交建议。

## 创建与读取

用户在 Space 首页点击 **新建文档** 创建标题为「未命名文档」、正文为空的文档。Agent 可以创建带完整初始正文的新文档；创建后，标题和正文的后续修改都只能通过建议完成。

文档身份、版本和源码区间在 [01](01-domain-model.md) 中定义。渲染只用于阅读，不参与坐标计算。

## 提交与决策

Agent 的每条建议携带基准版本、UTF-16 左闭右开区间、预期原文和替换文本。服务端按事务校验版本与锚点：

- 真正重叠的建议被拒绝，并返回冲突建议 ID 和可用定位。
- 版本冲突返回 `VERSION_CONFLICT`，Agent 必须重新读取最新正文。
- 锚点失效返回 `ANCHOR_STALE`，不允许猜测位置。

用户在右侧批注槽或正文高亮中逐条 **接受** 或 **拒绝**。接受后正文更新并递增版本；拒绝保持正文不变。决策通过操作 ID 幂等，刷新或重启后重新读取权威状态。界面状态和交互见 [03](03-ui-spec.md)。

## 评论

用户在渲染后的正文中选中文字，点击选区旁的 **评论** 保存评论；评论锚定到源码范围，可在后续版本中唯一映射时自动跟随，否则进入「位置已失效」分组且不绘制错误锚点。

评论默认只保存在本机，不会自动发送。用户点击顶部或右侧栏的 **全部发送** 时，当前文档的可发送评论作为一个请求发送到当前对话；没有打开的对话时先确认，再复用最近工作区或创建默认工作区并新建对话。发送失败和结果未知分别记录，结果未知不会自动重发。

## 宿主边界与验收

真实对话中的多文件选择、引用解析、评论发送和重启恢复需要在目标 DSH 版本逐项验收，当前接入状态和剩余项见 [04](04-dsh-integration.md) 与 [06](06-delivery.md)。插件不宣称能拦截宿主文件或 shell 的旁路写入。
