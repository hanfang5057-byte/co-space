# 07 · Markdown 文本审阅内核

正文以 Markdown 源字符串存储。创建时保留原始字符串；读接口通过 `content` 返回 Markdown 文本、正文版本和建议。建议是独立 SQLite 记录：基准版本、UTF-16 左闭右开坐标、预期原文、替换文本、上下文、创建顺序、建议人和创建时间。新增、删除、修改统一表示为文本替换。建议不直接改变正文，只有用户接受才应用。

文档没有待处理/冲突建议和当前评论时，用户可切换到可见即所得编辑模式直接修改正文。已接受/拒绝的建议及已发送/已处理评论历史不阻止编辑。保存使用基准版本和幂等操作 ID；核心层在同一写事务内再次检查版本及当前建议/评论，任何条件变化都会拒绝保存。保存成功后递增正文版本并写入变更历史。

提交在 SQLite `BEGIN IMMEDIATE` 事务内校验版本、代理对边界、预期原文和重叠。不同范围的建议可并存；同一位置插入按创建顺序排序；插入在修改范围端点归属范围外侧，范围内部插入和真正重叠返回冲突。接受正文后根据变更历史映射其他建议及评论；映射后必须再次校验预期原文。不能安全定位的建议保留并标记冲突。拒绝关闭建议而不改变正文版本。操作 ID 幂等。

`markdown-text-v1` 数据库通过事务迁移为 `markdown-text-v2`，保留文档、建议和评论。存在文档表但缺少已知 schema 标记或标记版本未知时，启动失败并保留原库；不会自动清空未知格式的数据。新数据库直接创建为 v2。旧建议的建议人记为 Agent；因旧数据没有创建时间，界面显示时间未知。新建议会保存准确创建时间。评论锚点直接使用 Markdown 字符串坐标；渲染预览选区与源码区选区都映射为 UTF-16 偏移。待处理建议在渲染后的正文中呈现删除线和新增文字，整块删除也保留原 Markdown 块级样式；右侧卡片只提供建议人、时间及决策按钮。Markdown 预览关闭原始 HTML。

待处理建议的 Markdown 预览先把建议应用到临时正文，再解析和渲染这份投影；删除与新增标记叠加在投影结果上。这样格式、链接和块结构由同一份将被接受的 Markdown 决定。整块删除后若其文本没有对应的投影 token，会把删除内容按原 Markdown 渲染，并插在投影中的对应位置。未受建议影响的渲染区间及删除内容通过投影映射回原正文的 UTF-16 偏移；建议插入文本不伪装成已接受源码。去掉差异标记后，预览结构须与接受替换后的正文渲染一致。冲突建议不进入投影。

验证入口：`npm run build:client` 和 `npm run check`。完整宿主端到端流程仍需在目标 DSH 环境验收。
