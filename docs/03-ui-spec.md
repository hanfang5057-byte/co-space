# 03 · 界面与交互规格

颜色、字体、圆角由宿主主题契约决定，宿主只通过 `--cospace-*` token 定制；本文只定义布局与交互，样式规范见 [19-web-theme-contract.md](19-web-theme-contract.md)。

## 入口

宿主左侧 CoSpace 总入口进入文档首页；首页「新建文档」按钮创建默认标题「未命名文档」、正文为空的文档。任意 DSH 对话输入框加号可选一个或多个 CoSpace 文件，用户发送修改要求。Agent 也可新建文档并直接写入完整初始正文；已有文档后续修改须经建议。宿主接入仍待验证。

## 主工作台两级页面

CoSpace 主工作台分为文档首页和文档预览页。首页展示全部个人文档卡片、待处理建议总数和「新建文档」；文档按更新时间倒序排列，点击卡片进入对应预览页，创建文档后也直接进入该文档。首页卡片展示标题、更新时间（无更新时间时回退到创建时间）和待处理建议数量，并提供删除操作。无文档时显示引导说明和创建入口。

预览页 header 左侧显示回退按钮和当前文档标题；回退回到文档首页，不改变文档状态。header 右侧保留建议/评论计数、刷新和「让 Agent 处理评论」。处理方式由适配器声明的会话发送、会话创建和剪贴板能力决定；不可用能力不显示，保留可用的降级入口。正文审阅区维持原有布局与交互。首页和预览页都填满宿主主内容列，各自管理滚动，不依赖外层页面滚动。

## 审阅布局

借鉴 Word 的审阅体验，采用宿主视觉语言，不复制其界面：左侧为渲染后的 Markdown 阅读区，右侧为统一的建议和评论卡片槽；正文不直接编辑。顶部显示文档标题；建议/评论计数、刷新和「让 Agent 处理评论」合并到顶部 header，返回 CoSpace 的入口保持在宿主导航中。

预览纸张采用固定 A4 纵向尺寸（96dpi 下约 794 × 1123 CSS px），正文排版宽度不随可视区域变化；窄屏通过画布滚动查看，不压缩纸张或重排正文。缩放控件按 10% 步进对纸张、内容及批注标记等比例缩放。批注栏使用固定宽度；画布宽度不足以同时展示纸张与卡片时，批注卡片改为锚点悬浮查看，不挤压纸张。界面与阅读正文均优先使用操作系统 UI 字体，不依赖特定第三方字体安装。

```text
┌ 文档标题 ───────────────────────────  待处理 3 ┐
│ 正文阅读区                      │ 修改建议     │
│ Markdown 渲染预览               │ 1 修改前/后 │
│                                 │   接受 拒绝 │
│ 标题、列表等结构预览            │ 2 修改前/后 │
│                                 │   接受 拒绝 │
└─────────────────────────────────┴─────────────┘
```

正文由 Markdown 源文本渲染且不可直接编辑；空白文档的纸张至少保持一页 A4 的高度。待处理建议直接在预览正文内显示删除、新增和替换，使用删除线与新增标记区分。Markdown 结构标记之间的插入也按原结构呈现。右侧精简卡片显示建议人、建议时间、变更类型与序号，以及「接受」「拒绝」操作；点击卡片会定位到对应正文范围。接受才改变已接受正文，拒绝保持正文不变。列表、表格和其他结构都按普通源码范围修改，不另建结构化决策模型。

点击卡片会滚动到正文并高亮对应源码范围；渲染节点带有源码区间，点击定位、正文高亮与批注连线都使用同一套映射。长文档下卡片顺序依源码位置排列；显示加载、无建议、操作中及失败状态；冲突建议不可决策，刷新或重启后重读最新状态。

修改建议和评论不再拆成两个区域：两者都进入正文右侧的 Word 式批注槽，按正文锚点排列，用不同色彩和连线区分；建议卡片保留接受/拒绝，评论通过顶部操作显式请求 Agent 处理。文档主体设置最小宽度，窗口更窄时由正文区横向滚动，不再切换成上下堆叠的窄窗口分支。

## 滚动与宿主布局

宿主主内容列自身不滚动（`mainPanel` 固定高度、外层 `overflow:hidden`），因此 CoSpace 页面必须自己建立滚动区域，不能依赖页面整体滚动：

- 标题栏固定；左侧文档栏独立滚动，正文区与批注槽在同一个滚动容器中滚动，长文不会把标题推出视口。
- 文档主体有最小宽度；窗口不足时正文区横向滚动，批注槽始终位于正文右侧，不进入窄窗口堆叠分支。
- 页面高度始终填满宿主主内容列（`height:100%`），不出现第二层页面滚动或内容被裁切。

## 对话中的文档卡片

通过输入框「+」发送的 CoSpace 引用在消息里显示为一张文档卡片，而不是裸的 `space:<docId>` 文本：

- 卡片展示文档标题（标题未知时回退到文档 ID）和「CoSpace 文档」来源标识；消息其余文字保持原样。
- 点击卡片在当前对话右侧边栏打开该文档的审阅面板（正文、评论批注槽、建议决策与发送），并自动展开边栏；同一文档再次点击时定位已打开的标签页。
- 卡片只承担导航，不修改正文，也不自动发送评论。
- 队列预览、本地回显等只读场景中的卡片不可点击，但仍显示为卡片。
- 正文标签页以 `cospace://document/<docId>` 作为内容地址，刷新或重启后可恢复同一文档。
- 用户主动请求处理评论时，适配器通过其声明的会话能力发送该文档的 `space:<docId>` 引用和简短指令，不将评论正文放入会话消息；无会话发送能力时，仅在剪贴板能力可用的情况下提供复制方式。
- 右侧审阅栏顶部保留同样的批注计数和评论处理按钮，不需要先回到 CoSpace 主页面。

## 评论

用户直接在渲染后的正文中选中文字后，选区旁出现「评论」按钮；点击打开评论对话框，输入并保存评论。渲染文字与 Markdown 源码的 UTF-16 区间互相映射，评论保留源码范围与引用文字；点击评论卡片会滚动并高亮正文引用范围。评论可多次添加、可删除；评论状态覆盖发送和 Agent 处理阶段。处理完成后评论从批注槽隐藏，关联建议仍保留各自的审阅状态。

评论锚点记录创建时的引用文字、坐标和上下文。文档版本变化但引用仍可唯一定位时自动映射到新位置；无法唯一定位时进入「位置已失效」分组，保留引用但不绘制正文锚点，不猜测位置。

用户通过顶部或右侧审阅栏的刷新按钮重新读取文档、建议和评论，以查看 Agent 刚提交的修改。用户通过「让 Agent 处理评论」显式触发当前未处理评论的处理；评论不会自动进入对话。适配器按协商后的能力发送文档引用和短指令，或提供可用的复制降级。Agent 从 `space_document_read` 获取评论，提交建议后调用 `space_comment_complete` 记录关联；完成处理的评论随即从批注槽隐藏。建议处理完成并不改变正文，正文仅在用户接受建议后变化。

评论卡显示当前登录 DeepSeek 账号的显示名和头像；账号未登录、账号插件缺失或资料读取失败时回退到本地化通用作者，不显示联系方式和凭据。

建议差异直接标注在预览正文中，正文中建议与评论分别用不同色彩的标记，并通过连线连接到右侧对应卡片；评论卡片仍显示评论内容。

## 可用性与验收

所有操作键盘可达，有可见焦点和清楚的辅助技术名称；状态不只靠颜色表达。支持长文滚动、最小正文宽度及横向滚动。

- 10–20 个待处理单位可定位、逐个接受或拒绝；相邻修改合并后整体决策。
- 卡片与正文双向定位，前后内容可辨；失败不会误改正文。
- 可多次评论并显式请求 Agent 处理；创建评论不自动触发处理；评论可删除；建议与评论在同一个批注槽内可区分、可定位；建议内容按删除/新增/修改/格式分类展示；锚点失效有独立分组且不绘制错误连线。
- Agent 新建带完整正文的文档后，对现有文档的修改必须提出建议。
- 重叠提交明确报错；并发、恢复满足 [01](01-domain-model.md#事务与恢复)。
