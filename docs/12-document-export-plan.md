# 12 · 文档导出方案

## 目标与范围

在文档详情页提供导出入口，当前支持 Markdown（`.md`）和 Word（`.docx`）。PDF 导出已移除，待宿主打印能力问题解决后再评估。导出单篇文档的已接受正文快照，供用户保存、阅读和继续编辑；不改变文档、建议或评论状态。批量导出、导入、导出审阅痕迹及评论暂不纳入首期。此方案扩展 [导入与导出原则](05-word-export.md)，不改变其中的审阅边界。

## 用户体验

- 文档详情页工具栏增加“导出”，打开格式菜单，提供 Markdown 和 Word 两项；无可用文档或正在获取快照时禁用，并支持键盘操作和明确的无障碍名称。
- 菜单中说明“仅导出已接受的正文，不包含待处理建议和评论”。即使页面上显示插入、删除预览，导出内容也以此说明为准。
- 用户选择格式后读取一次最新文档，固定其正文、标题和版本，之后基于同一快照生成文件。读取或生成失败时显示可理解的错误并允许重试；文档被删除时提示文档已不存在。生成期间切换文档不会改变本次导出的目标。
- 默认文件名取快照标题，清理路径分隔符、控制字符和操作系统不支持的字符，限制长度；空名称使用“未命名文档”，并添加对应扩展名。保存位置由宿主或浏览器决定，用户取消保存不报错。

## 数据与一致性

当前 `SpaceService.readDocument` 返回的 `content` 是已接受正文；`suggestions` 和 `comments` 是独立的审阅信息。详情页 `renderMarkdown(doc.content, doc.suggestions)` 会生成含待处理修订的预览，因此**不得直接截取当前审阅 DOM 作为导出内容**。

导出动作通过现有只读接口获取目标文档一次，立即复制 `id`、`version`、`title`、`content` 构成不可变快照；生成只使用快照，不读取建议和评论，也不调用决定建议或写入接口。并发修改发生在读取之后时，导出的是该次读取的版本，不自动混合新旧内容；读取失败不使用可能过期的界面缓存冒充最新版本。标题已包含在 Markdown 正文时不额外插入标题，避免重复。若导出执行时间较长，可在状态提示中展示快照版本。

## 格式与转换

| 格式 | 内容和行为 | 首期要求与限制 |
| --- | --- | --- |
| Markdown | 以 UTF-8 保存快照 `content` 原文，不附加审阅数据或重新排版 | 保留原有换行和 Markdown 标记；保留图片链接，不打包外部资源。 |
| DOCX | 将 Markdown 解析为结构化内容，再转换为真正的 Office Open XML 文档 | 主要结构可在 Word / WPS 中编辑；保留标题层级、段落、强调、链接、列表、引用、代码块和表格；不以 HTML 或纯文本冒充 `.docx`。 |

现有渲染器使用 `markdown-it` 且禁用原始 HTML。导出应以相同的 Markdown 语义为基准，优先复用解析规则，而不是复用含建议投影的 HTML；为 DOCX 维护明确的 token 到文档元素映射。嵌套列表、表格、代码和换行以样例验证；无法保真转换的语法要有明确降级规则，不能静默丢失正文。图片、远程链接、复杂嵌套和超长表格的精确表现需要原型验证：首期不得自动请求远程图片或读取任意本地路径；无法安全获取的图片以可见替代文本和原始链接保留，并在界面说明。Markdown 导出继续保留原链接。对于不安全的链接协议，不生成可执行链接，保留可读文本。

## 架构与实现路径

1. **先验证宿主能力。** DSH 客户端由 `scripts/build-client.mjs` 打包为浏览器代码并运行在宿主环境。验证 DSH 对 Blob 下载和文件名的支持，记录实际运行环境和限制，不能仅凭普通浏览器测试推断宿主行为。
2. **共享导出模块。** 在 `packages/review-ui` 或独立的宿主无关包中实现快照到 Markdown / DOCX 文件内容的纯转换，以及文件名处理。选用适合浏览器打包的 DOCX 库，核查许可证、包体积、离线能力及 Node 24 / 构建目标兼容性，再锁定依赖。
3. **保存能力适配。** 将生成和保存分离：界面通过[适配器契约](14-adapter-integration.md)的文件保存能力保存文件。若 DSH 不支持 Blob 下载，设计最小宿主桥接方案后再实施；不可将文档发送到第三方服务。仅在所需能力可用时开放对应选项；不支持时解释原因。
5. **界面与文案。** 在共享详情页工具栏接入导出菜单、加载和错误状态，更新共享及 DSH 所需中英文文案，处理焦点、Escape 和菜单关闭。保持现有选择正文、审阅和手动发送评论流程。
6. **构建与发布适配。** 检查 DSH 适配器依赖、打包清单和运行时，确保新增资源在离线安装包内；评估包体积。无需修改 `review-core.js` 或改变 review-core 行为；若验证证明必须改变，先单独说明并取得用户同意。

## 安全与隐私

正文仅在当前本地运行环境处理，不上传转换服务，不写入日志、遥测或错误信息。转换不执行原始 HTML、脚本或不安全链接；限制生成文件名与资源访问，防止路径穿越和意外访问本地文件。临时对象 URL 或临时文件使用后及时清理。导出文件属于用户主动保存的副本，后续不随源文档更新。

## 验证与验收

- **一致性与只读：** 构造包含待接受、待拒绝及冲突建议和评论的文档，验证两种格式均只含读取版本的已接受正文；导出前后正文、版本、建议、评论及发送状态不变。覆盖读取后并发修改、文档切换、删除和失败重试。
- **格式：** Markdown 字节内容与快照正文按 UTF-8 一致；检查 DOCX 结构并用 Word / WPS 实际打开、编辑。用同一份包含标题、列表、引用、链接、表格、代码、中文及图片的样例对照；记录降级和不支持的内容。
- **交互与安全：** 验证空文档、长标题、特殊文件名、取消保存、生成失败、键盘操作、焦点、危险链接及禁止远程图片请求；验证不会将审阅标记、评论或界面控件带入文件。
- **宿主与构建：** 在真实 DSH 宿主完成两格式保存的人工验收，记录宿主版本与限制；运行聚焦自动化测试、`npm run check`、`npm run build:client`、`sh scripts/test-ui.sh` 和 `npm run verify:dsh-package`。模拟 DOM 和构建通过不能替代真实宿主验证。

## 实施顺序与决策点

当前实现进度（2026-11-23）：共享详情页提供 Markdown 和 DOCX 导出；导出前从 `readDocument` 重新获取已接受正文快照。PDF 打印入口已移除，因为宿主打印行为仍有问题；恢复前需在真实 DSH 宿主中验证方案。

实现选型记录：原计划优先评估 `docx` 等成熟库；当前开发环境无法访问 npm registry，且本地无包缓存，因此没有引入该库。DOCX 当前采用最小 OOXML 生成器，覆盖标题、段落、常见行内强调、HTTP(S)/mailto 链接、列表、引用、代码块和基础表格；图片目前只作为替代文本处理，嵌套列表和复杂 Markdown 未验证。

已验证记录：此前导出单测、构建通过；真实 DSH 下载尚未验收，DOCX 尚未用 Word/WPS 实际打开和编辑。PDF 导出目前已移除。
