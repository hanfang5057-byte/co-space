# 06 · 交付与验收

## 顺序

1. **验证关键假设**：在目标 DSH 版本核对加号多文件接入、左侧入口、当前对话和用户主动触发处理接口；验证 Markdown 文本替换建议的分组、独立决策、持久化及恢复。记录证据与缺口，不把候选当成已选定方案。
2. **实现文档与审阅内核**：确定事务性持久化和文档坐标，完成版本校验、重叠检查、逐条决策、锚点映射及崩溃恢复。Agent 可创建带初始正文的新文档，已有文档只能提交建议。
3. **打通界面与对话**：左侧浏览、加号多选、建议逐条审阅、选区评论及显式评论处理请求；明确失败和未知状态。
4. **端到端验证**：真实宿主中完成下列验收，确认后再考虑可选导出。时间与工作量在技术验证后估算。

## 功能验收

- [ ] 用户在 CoSpace 页面点击「新建文档」，创建默认标题「未命名文档」、正文为空的文档；列表与审阅页正确显示，创建不产生覆盖。
- [ ] Agent 创建新文档并写入完整初始正文；不能以创建接口覆盖已有文档，后续修改走建议决策。
- [ ] 任意 DSH 对话中通过加号选择一个或多个 CoSpace 文件并要求修改；Agent 获取正确文档和版本。
- [ ] 发送后的引用显示为文档卡片；点击卡片展开右侧边栏并打开对应审阅面板，刷新后仍恢复同一文档。
- [ ] 长文档下审阅页面在宿主主内容列内独立滚动：标题栏固定，正文、文档栏和批注槽可达；正文有最小宽度，窗口不足时横向滚动且不裁切内容。
- [ ] Agent 提交具体建议后，已接受正文不变；用户逐条接受才改变对应正文，拒绝不改变正文。覆盖 10–20 条待处理建议及刷新重启。
- [ ] 相邻非空修改合并为一个接受或拒绝的单位。重叠提交返回 `OVERLAPPING_SUGGESTION` 和冲突 ID，原建议与正文不变；覆盖同点插入、插入位于范围边界、非空范围首尾相接。
- [x] 多条评论分别锚定选区，创建后不自动触发处理；评论以批注槽气泡和连线关联正文；评论卡显示当前 DeepSeek 账号名称/头像（取不到时回退通用作者）。用户主动请求 Agent 处理后，Agent 从指定文档读取评论并将建议关联回评论；评论完成处理后隐藏，关联建议保留其独立决策状态。
- [ ] DSH 真实宿主中，从审阅栏触发处理时能正确取得当前对话；无当前对话时复用/创建会话并发送文档引用和短指令；创建/发送失败保留评论并提示。右侧审阅栏可直接触发，无需返回 CoSpace 主页面。
- [ ] Agent 通过 `space_suggestion_list` 能看到建议的待处理、接受、拒绝和冲突状态；不依赖猜测正文变化来判断用户决定。
- [ ] 锚点版本变化但引用仍可唯一定位时自动映射；不能安全映射时标 stale，保留评论引用，进入失效分组且不绘制正文锚点；格式及结构性修改不会被当作无变化。

## 一致性与集成验收

- [ ] 并发重叠提交只允许一个成功；过期版本返回 `VERSION_CONFLICT`，不存在检查与保存之间的竞态。
- [ ] 并发接受/拒绝与重复请求不会重复应用；接受一条后其余建议安全映射或明确 stale。
- [ ] 对事务提交前、中、后注入失败及重启：正文、建议状态、版本和映射恢复为完整的事务前或事务后状态；提交成功后丢失通知可通过重读恢复。
- [ ] 评论处理期间的会话失败、超时和结果未知在真实宿主中有明确反馈；工具操作按稳定请求 ID 幂等，不自动重复生成建议。
- [ ] Agent 可用接口没有正文直写能力；实际宿主文件/shell 权限边界有单独验证和准确说明，不把产品约束描述为沙箱。
- [ ] 键盘可完成建议决策及评论处理触发，错误、焦点和状态可感知。

## 待决技术风险

| 风险 | 验证或应对 |
|---|---|
| 候选库的建议分组、相邻合并和独立决策不符合要求 | 用真实场景验证；验证合并结果与决策单位，必要时替换候选 |
| 复杂结构或格式变更无法可靠定位及比较重叠 | 定义统一坐标，无法可靠判断时拒绝并报告，不猜测 |
| 正文和建议状态跨持久化步骤不一致 | 采用可证明原子提交和恢复的存储方案，进行故障注入 |
| 宿主接入或消息发送契约与预期不同 | 按目标版本验证；发送结果未知时保留状态并提示用户 |
| 外部工具绕过 CoSpace 写入 | 验证宿主权限并如实说明；不能以提示词或未验证 guard 宣称隔离 |
