# 05 · 导入与导出

核心场景是浏览文档、Agent 提建议、用户逐条决策和主动发送评论；导入导出不是该闭环的前置条件。Markdown 可用于 Agent 交换及显式导入导出，但不规定它为内部事实源。导入是否替换或创建文档、格式损失和与已有建议的关系须在具体功能设计时明确；不能通过导入绕过既有文档的用户审阅决策。

Word（`.docx`）导出可作为后续可选能力，当前不以它扩大核心范围。若实现，默认导出当前**已接受正文**的快照，不隐式接受待处理建议，也不包含待处理建议或评论；UI 应说明导出内容。导出前后正文及建议状态不变。

导出实现、格式覆盖、图片及字体兼容性均须单独验证；不能以旧 Markdown 内核方案的估时或试验结论证明新内部表示可直接导出。验收至少检查导出内容与所选版本的已接受正文一致，含待处理建议时不将其误写为已接受正文，失败不改变文档状态。
